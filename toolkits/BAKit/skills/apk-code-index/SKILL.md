# APK Code Index

The decoded tree of a real app holds 10,000–150,000 files. Reading it raw spends the context of
whoever does it on SDK code nobody asked about. **Orient with the index, then read the few classes it
points at.** jadx output is a viewer for a class you have already located, never the place to start.

Script: `.agents/skills/apk-code-index/scripts/apk_index.py` (Python 3.8+, standard library only).
It understands both jadx layouts: `--export-gradle` (`app/src/main/{java,res,AndroidManifest.xml}`,
what ReaKit produces) and the default (`sources/` + `resources/`).

## 1. Build the index (once per app version)

```powershell
python .agents/skills/apk-code-index/scripts/apk_index.py build "<jadx_src>" --out docs/BA/competitor/<app-slug>/code-index
```

It finishes in seconds and writes six files, each under 250 lines:

| File | Holds | Read it for |
| :--- | :--- | :--- |
| `_meta.md` | package, jadx root, app packages, counts | Start here; check the app packages are right |
| `screens.md` | launcher, deep links, activities with their layout, nav graphs, fragments | The screen map: what exists and how it links |
| `packages.md` | sub-packages of the app by size | Feature areas (`.../transfer`, `.../kyc`, `.../paywall`) |
| `endpoints.md` | URL literals and Retrofit paths, grouped by host | Backend domains, partner services, API surface per feature |
| `signals.md` | analytics event names, feature-flag and config keys | The funnel they measure; what they switch remotely |
| `tech.md` | version, frameworks, bundled SDKs, permissions, meta-data keys | Tech profile; cross-platform warning |

If `_meta.md` lists the wrong app packages (an SDK, or nothing), rebuild with
`--app-prefix com/example/app` (repeatable). If `docs/BA/competitor/<app-slug>/code-index/_meta.md`
already exists for the same version, read it instead of rebuilding.

## 2. Map a flow to code

```powershell
python .agents/skills/apk-code-index/scripts/apk_index.py find "<jadx_src>" "chuyển tiền|transfer|send money" --limit 40
```

Prints three sections: the string resources whose text or name matches (with the default, Vietnamese
and English text), the layouts that show those strings (`file:line`), and the app classes that reference
them or match the pattern. It resolves `R.string.x`, obfuscated R classes (`AbstractC13406f.x`) and raw
numeric ids. Search in both the app's language and English, and in resource-name style
(`transfer|chuyen_tien|send_money`). `--scope all` widens the class search beyond the app packages.

Then open only the classes it names, with `view_file`, and read for:

- **Validation and limits**: `length() <`, `> 50000000`, regexes, error string ids → observed-on-device candidates.
- **Branches the UI hides**: `if (user.isKyc…)`, remote-config keys, A/B variants → screens the walker may not reach.
- **Navigation**: `navigate(R.id.x)`, `startActivity(new Intent(…, X.class))`, `putExtra` keys → edges for the flow map.
- **Server-driven UI**: DTOs named `*Config`, `*Banner`, `*Tab*`, `*Menu*` with `enabled`/`order` fields → the
  screen is configured by the backend, so what the walker sees may differ by account or region.

## 3. Evidence grades

Every fact taken from code is **code evidence** and is graded as such in BA documents:

| Grade | Means | Example |
| :--- | :--- | :--- |
| `[Observed]` | Seen on the device, cites a capture under `screens/` | "Button 'Tiếp tục' disabled until 10 digits" |
| `[Code]` | Present in decoded code, cites `file:line`; not seen on device | "Transfer limit 50,000,000 VND in `TransferValidator.java:88`" |
| `[Inferred]` | Reasoned from either; says what it rests on | "Likely a KYC gate before transfer, from `KycGuard` + error string" |

A screen in `screens.md` exists in the code; it is not proof users can reach it. Dead code, feature-flagged
and A/B screens are common. Never write a `[Code]` fact as if it were observed.

## Rules

- Read-only over `jadx_src/`: never edit, move or delete decoded files; they are regenerated by ReaKit.
- Never copy secrets out of the code: API keys, tokens, signing secrets, credentials, private endpoints'
  auth headers. Name them (`"Google Maps key present in manifest meta-data"`), never quote the value.
- Cite every code fact as `path:line` relative to the jadx root, the same form the index uses.
- Cross-platform apps (Flutter, React Native, Unity): `tech.md` says so. The Java/Kotlin side is mostly the
  runtime; screens live in Dart/JS bundles. Rely on endpoints, strings, assets and the device instead.
